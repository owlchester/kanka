# Custom category statuses

All paths below are relative to `/api/1.0`. Use the existing Passport bearer token authentication and campaign access rules. The existing API rate limits apply.

Custom status definitions are available only for **premium campaigns' custom categories**. Built-in categories retain their application-defined statuses. There is a limit of **10 definitions per custom category**, with case-insensitively unique, nonempty labels of up to 45 characters. Statuses do not impose transitions or trigger automation.

In the UI, statuses with icons display the icon with an accessible label/tooltip; iconless statuses display their label as text.

## Read definitions

```http
GET /campaigns/{campaign}/category_statuses
GET /campaigns/{campaign}/entity_types/{category}/statuses
```

The first endpoint includes global definitions and definitions owned by the current campaign. The second lists only the specified campaign-owned custom category's definitions. Results are ordered by category, configured order, and identifier. Both remain readable after premium expires.

Each definition contains:

```json
{
  "id": 1000,
  "key": "investigating",
  "name": "Investigating",
  "label": "Investigating",
  "icon": "fa-solid fa-magnifying-glass",
  "sort_order": 0,
  "is_default": true,
  "category_id": 42,
  "campaign_id": 123,
  "is_custom": true
}
```

`name` is the display name; built-in definitions resolve their translated name and have a null `label`. `icon` is a normalized CSS class string, or an empty string when absent. `id` and `key` remain stable when a label changes. Custom keys are generated by the server and are not editable.

IDs below 1000 are reserved for application definitions; new auto-allocated definitions start at 1000 or above. Existing IDs are never renumbered. Ownership must be determined from `campaign_id` and `category_id`, not ID ranges.

## Create and update

Requires campaign-settings permission and premium eligibility.

```http
POST /campaigns/{campaign}/entity_types/{category}/statuses
PATCH /campaigns/{campaign}/entity_types/{category}/statuses/{status}
Content-Type: application/json

{"label":"Investigating","icon":"fa-solid fa-magnifying-glass","is_default":true}
```

Creation returns `201`, updating returns `200`, with a `data` definition object. `label` is required. Icons are optional, accept a Font Awesome icon token with an optional supported style prefix, and cannot contain HTML. `icon: null` removes the icon. Selecting a default clears the previous default. Setting the current default's `is_default` to `false` leaves the category without a default.

The category create/update endpoints also accept `statuses`, an ordered array of `{id?, label, icon?, is_default?}`. Existing definitions must retain their IDs and all existing definitions must be included when submitting this array. Omission of the entire `statuses` property leaves definitions untouched. Missing definitions are not implicitly deleted; use the deletion endpoint. At most one submitted definition can be the default. Category and definition changes are saved atomically.

## Order

```http
PUT /campaigns/{campaign}/entity_types/{category}/statuses/order
Content-Type: application/json

{"ids":[1002,1000,1001]}
```

Supply every current definition ID exactly once. Returns the ordered collection in `data`. An empty array is valid only for a category without definitions.

## Assignment

Use `status_id` in the existing entry endpoints:

```http
POST /campaigns/{campaign}/entities/{category}

{"entities":[{"name":"The locked room","status_id":1000}]}
```

```http
PATCH /campaigns/{campaign}/entities/{entity}

{"status_id":null}
```

| Operation | Behaviour |
| --- | --- |
| Creation: omitted `status_id` | Apply the category default, if any. |
| Creation: explicit `null` | Leave unassigned, even with a default. |
| Update: omitted `status_id` | Preserve the current assignment. |
| Update: explicit `null` | Clear the assignment. |
| Change the category default | Existing entries are not updated. |

A non-null assignment must belong to the entry's campaign **and** category. On downgrade, assignments remain readable and unchanged by unrelated edits. Clearing is allowed, but new assignments and definition management are blocked. Same-category copies preserve the source assignment; cross-campaign transfers clear campaign-owned statuses rather than reusing foreign IDs.

Entry responses retain `status_id` and additionally expose the resolved definition in `status`, or null when unassigned.

## Filter

```http
GET /campaigns/{campaign}/entities?type_id={category}&status_id=1000
GET /campaigns/{campaign}/entities?type_id={category}&status_id=none
```

`none` explicitly selects entries with no status; omitting `status_id` applies no status restriction. Existing array filtering also supports multiple IDs.

## Delete safely

```http
DELETE /campaigns/{campaign}/entity_types/{category}/statuses/{status}

{"replacement_id":1001}
```

Alternatively:

```json
{"clear":true}
```

Assigned definitions cannot be deleted without an explicit replacement or clear choice. Replacements must be another definition in the same category. A successful deletion returns `204`.

Replacement updates all assignments, including soft-deleted entries, and saved bookmark/widget filter references. Replacing a deleted default transfers the default to its replacement; clearing removes the default. These maintenance updates do not bump entry modification timestamps or flood recent widgets.

Incremental API clients using `lastSync` should refresh affected entries when definitions are deleted/replaced: these maintenance reassignments deliberately preserve entry timestamps.

When clearing, affected saved filters become a nonmatching `deleted:{id}` sentinel until explicitly edited. They are never silently removed or broadened. If a multiselection includes a deleted sentinel, the filter fails closed until repaired.

## Errors

- `401`: authentication required.
- `403`: missing settings/entry-edit permission or premium eligibility.
- `404`: missing definition, foreign category/definition, or attempts to manage a built-in category.
- `422`: invalid input, duplicate labels, limit reached, wrong-category assignments, invalid order, stale category definition set, or missing explicit deletion choice. The existing API error format includes a `fields` map.

Campaign exports include definitions with custom-category metadata. Import creates destination definitions before entries and remaps IDs; missing/legacy definitions are cleared rather than trusted as destination IDs.
